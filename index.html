Overview

Three tracks connect recognition, corrective capability, and the impact of online intervention.

Our key concern

Can a robot recognize a failure, repair the affected stage, and complete the original task?

Track 1

Streaming failure detection

Detect failures using only the execution history available at the query time. Evaluate alarm correctness and timing.

When should the robot intervene?

Track 2

State-conditioned stage recovery

Start from a shared failure state with a local stage goal and a fixed budget. Check whether the affected stage is repaired.

Can the robot repair this stage?

Track 3

Online task rescue

Compare matched executions with failure handling enabled or disabled. Measure final task outcomes, rescues, and harm.

Does intervention help finish the task?

Data generation

Source-policy rollouts, reviewed failure anchors, and independently checked corrective continuations.

Y-paired data

A shared execution prefix and failure state connect the original failed continuation with a corrective branch. Each branch retains its own stage and final-task outcomes.

Collect and review

Record policy rollouts and review failure onset, the affected stage, and failure type.

Generate corrections

Collect corrective references through automated recovery and human teleoperation.

Verify and split

Check stage and task outcomes separately. Keep a source episode and all its variants in one split.

Research Q&A

Three questions connect the benchmark tracks to the paper’s analyses.

01

How accurate and timely are failure detectors?

Detection correctness and alarm timing describe different behaviors. We examine both, together with visual-shift robustness, transfer across domains and source models, and query latency.

Final analysis pending
02

Which failure types can recovery methods repair?

Category-wise stage recovery reveals which failures each method can address. Matched cases identify shared successes, additional recoveries, and failures unresolved by the evaluated methods.

Recovery measurements pending
03

When does local recovery improve final task outcomes?

Independent stage checks and execution traces connect local repair to later task completion. Paired OFF/ON outcomes distinguish rescues, preserved successes, harms, and unresolved failures.
