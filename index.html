Track 1

Streaming failure detection

Detect failures using only the execution prefix available at query time. Evaluates onset alignment and false alarms separately from query latency under Lorentzian timing weights w(d).

When should the robot intervene?

Track 2

State-conditioned stage recovery

Start from a reconstructed shared failure state s* under common local goals and physical budgets. Checks stage repair independently of final task completion.

Can the robot repair this stage?

Track 3

Online task rescue

Run matched initializations with intervention disabled (OFF) or enabled (ON) under a shared total budget. Quantifies both rescued failures (R) and disrupted baseline successes (H).

Does intervention help finish the task?

Research Q&A

Four empirical findings connect failure detection, local repair, takeover timing, and final task completion.

01

Do high-accuracy monitors actually detect failures on time?

Finding: Episode accuracy hides late alarms, protocol blow-ups, and visual-shift drops.

On 1,500 sequences, STAC reaches 70.60% bACC but falls to 53.44% TWAΔ due to delayed triggers. Prompting protocol also dominates API monitors (GPT 6.1 Sol FPR jumps from 9.87% prefix to 89.33% window), while FailSafe VLMs drop 7.49–16.97 points under background randomization.

02

Which capabilities separate recovery paradigms?

Finding: No single recoverer dominates every capability—paradigms are strongly complementary.

Astra leads overall at 32.99% Stage SR (+17.53 over FailSafe), yet the 7 methods jointly cover 383/750 (51.1%) with 135 cases solved only by non-Astra methods. FailSafe (28.5%) and Recovery-SFT (25.4%) surpass Astra on bimanual coordination, while 367 cases remain unsolved by all seven.

03

Does earlier intervention uniformly improve stage recovery?

Finding: Takeover-time curves are non-monotonic—earlier triggers do not guarantee better recovery.

Shifting intervention across −1.0 to +3.0 s around reviewed onset on fixed source trajectories yields no monotonic gain for either Astra or SFT-6k across 33 ManiSkill parents (99 attempts per offset).

04

When does local repair translate into final task completion?

Finding: Local stage repair and positive self-verification do not guarantee net online rescue.

Resuming the source policy after 388 stage-success endpoints completes only 195/388 tasks, leaving 193 (49.7%) incomplete. Online, false interventions can also harm baseline successes (BGR ΔSR −4.07; CycleVLA −13.89), while FastWAM/Astra records ΔSR = +0.00.
